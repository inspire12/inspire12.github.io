추천 피드의 그룹별 캐싱

사용자가 홈 피드를 열 때마다 만들던 추천을 응원 팀별로 미리 준비했습니다.

#그룹 단위 캐싱#추천 피드

개발 서버에서 재현한 조회 지연

홈 피드가 사용자별 추천 API의 응답을 기다리는 동안 서버 스레드도 대기했습니다. 추천 요청이 밀리면 홈 피드까지 타임아웃이 났습니다.

개발 서버에서 Locust로 홈 피드 API를 호출했습니다. 가상 사용자가 100명을 넘자 밀리초 단위였던 응답 시간이 초 단위로 늘어났습니다.

개인별 실시간 추천에서 응원 팀별 배치로

홈 화면에서 개인마다 다른 추천을 제공하던 범위를 응원 팀 단위로 좁혔습니다. 같은 팀 팬에게 같은 피드를 제공하면, 한 번 계산한 추천 결과를 여러 조회 요청에서 쓸 수 있었습니다.

여러 서비스에서 보낸 데이터를 culogger에서 모아 형식을 맞추고 AI 팀의 Curation Platform에 전달했습니다. 추천 결과는 배치로 갱신하고 홈 피드는 팀별 캐시에서 읽도록 바꿨습니다. 외부 추천 API 호출에는 서킷브레이커를 적용해 실패가 반복될 때 추가 호출을 제한했습니다.
