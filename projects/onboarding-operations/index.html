온보딩·배포·모니터링 개선

온보딩과 배포, 모니터링 개선에 참여했습니다. 입사 초기에는 일부 인스턴스에서만 나타난 문제를 팀과 함께 추적했습니다.

#스케일 아웃#배포 복구#인스턴스 버전 검증

문제 인식

입사한 지 사흘째였습니다. 오후 두 시쯤 빌드만 해둔 상태였고, 퇴근 후 사용자 문의가 들어오면서 일부 사용자에게 문제가 생긴 걸 알았습니다.

팀과 함께 AWS 모니터링을 보니 저녁 여섯 시쯤 사용자가 늘면서 스케일 아웃이 일어났고, 그 시점에 문제가 시작됐습니다.

장애 대응

일부 사용자에게만 문제가 생겨서, Elastic Beanstalk에서 새로 늘어난 인스턴스와 기존 인스턴스의 빌드 버전을 비교했습니다. 서로 다른 버전이 실행 중이었습니다.

팀은 이전 버전을 다시 빌드해 배포했고, 인스턴스의 빌드 버전을 맞췄습니다.

재발 방지

복구 후에는 GitHub Actions에서 latest 태그로 빌드하던 방식을 바꿔, 빌드할 때 버전을 명시하도록 수정했습니다. 스케일 아웃으로 인스턴스가 늘어날 때도 배포한 버전이 실행되도록 했습니다.
